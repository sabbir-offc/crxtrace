# CrxTrace docs site

The source for [crxtrace.dev](https://crxtrace.dev). Built with
[Astro](https://astro.build) + [Starlight](https://starlight.astro.build),
deployed to Cloudflare Pages.

This is a separate npm project from the SDK at the repository root — it has its
own `package.json` and dependencies, and none of it ships in the published
`crxtrace` package.

## Local development

```bash
cd docs
npm install
npm run dev      # http://localhost:4321
```

| Script | Does |
| --- | --- |
| `npm run dev` | Dev server with hot reload |
| `npm run build` | Production build into `docs/dist/` |
| `npm run preview` | Serve the built output locally |

## Where the content lives

```
src/content/docs/
├── index.mdx                  # landing page (splash template)
├── 404.md
├── getting-started.md
├── migrating-from-sentry.md
├── guides/
│   ├── worker-deaths.md
│   ├── content-scripts.md
│   ├── error-categories.md
│   ├── privacy.md
│   └── filtering.md
└── reference/
    ├── api.md
    ├── configuration.md
    ├── envelope.md
    └── self-hosting.md
```

Pages are plain Markdown with frontmatter — you don't need to know Astro to
edit them. Adding a page means creating the file **and** adding it to the
`sidebar` array in [`astro.config.mjs`](astro.config.mjs); the sidebar is
explicit rather than autogenerated so ordering stays deliberate.

Search (Pagefind) and the sitemap are generated at build time. Nothing to
configure.

## Keeping docs honest

The reference pages describe real behaviour, not intentions. When you change
the SDK, these need updating in the same PR:

| If you change | Update |
| --- | --- |
| An option or its default | `reference/configuration.md` |
| An exported function's signature | `reference/api.md` |
| Anything in `src/types.ts` | `reference/envelope.md` — it's a public contract |
| An `Mv3Category` value | `guides/error-categories.md` |
| Redaction rules | `guides/privacy.md` |
| Retry or response handling | `reference/envelope.md` and `reference/self-hosting.md` |

## Deployment

Deployed to **Cloudflare Workers** with
[static assets](https://developers.cloudflare.com/workers/static-assets/),
built from `main` on push.

Configuration lives in [`wrangler.jsonc`](wrangler.jsonc). It is a static-only
Worker — there is no `main` entrypoint, because Astro emits a fully static site
and Cloudflare serves those files directly.

`not_found_handling` is set to `404-page` rather than the
`single-page-application` default. The default answers `200` with `index.html`
for every unmatched path, which would turn a mistyped docs URL into the
homepage and let search engines index endless duplicates of it.

### Cloudflare build settings

| Setting | Value |
| --- | --- |
| Build command | `npm run build` |
| Deploy command | `npx wrangler deploy` |
| **Root directory** | **`docs`** |

**Root directory must be `docs`** (it's under *Advanced settings* when creating
the project). Left blank, Cloudflare builds the SDK at the repository root and
deploys that instead of the website.

### Deploying by hand

```bash
cd docs
npx wrangler login
npm run deploy          # builds, then deploys
```

Validate the config without deploying:

```bash
npx wrangler deploy --dry-run
```

The custom domain (`crxtrace.dev`) is configured on the Worker under
*Settings → Domains & Routes*.
